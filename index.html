How I build

One person, many AI agents

I build Class Cookies and its seven games by directing AI agents. I'm the product owner, designer and tester. Claude Code writes the code, nothing is built that I haven't decided on, and nothing is released until I say so.

Each of the eight products, the seven games and the Class Cookies platform, has its own repository and its own Claude Code sessions. Every session reads that repository's instruction file before it does anything else. Other sessions handle work that cuts across the products: this portfolio, and clean-up jobs such as checking every repository for a bug one session found in another.

Above the sessions sit two chat-based reviewers. Every session report goes to both. They check it against the brief, look for what was skipped or got through untested, and write the next prompt, which I paste into the session. They review the same work, and I pass each one the other's findings. As the brief puts it, "Disagreement is the product." Beside them, a separate chat-based Claude agent works on marketing: it analysed the market and drafted LinkedIn and Reddit posts.

I decide what gets built and design how it works in a classroom. I test the live sites myself and send back what I find. I use the games with my own classes most weeks, and colleagues have tried them in theirs. That is informal use, not a study, but it changes the design: Taco Trivia has no game-over screen, because final scores are counted after the last tile and a screen would cover the score panels.

On 7 October 2026, 694 of the 869 commits on the production branches carried a Claude co-author line. Git lists me as the author because I direct the agents and commit their work; it does not mean I typed the code.

The products themselves contain no AI: none of them calls an AI service.

  1. I write the brief: what to build, the rules, and a success criterion for each step.
  2. The product's session reads its instruction file, plans, and stops for my approval.
  3. It builds in small steps. A new test has to fail first. Done means typecheck, lint, tests and a production build all pass.
  4. The reviewers read its report and draft the next prompt.
  5. I decide and release, check the live site, and use the result in class.
